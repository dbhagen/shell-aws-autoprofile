# Autobuild orientation

shell-aws-autoprofile is a Bash/ZSH add-on that keeps AWS credentials scoped to the directory you are in. Sourced from `.bashrc`/`.zshrc` (or loaded as an Oh My Zsh plugin), it registers a directory-change hook that searches upward from the current directory for a `.awsprofile` file — falling back to `$HOME/.awsprofile` — and exports `AWS_PROFILE` from line 1 and `AWS_REGION` from the optional line 2. A line 1 of exactly `none` unsets `AWS_PROFILE` (the region line is still applied); the alert this prints is silenced only when `AWSPROFILE_IGNORE_EXPLICIT_NONE_PROFILE=true`. Developers juggling different AWS profiles across project trees use it so credentials follow the checkout automatically.

The product is two byte-identical script copies — `shell-aws-autoprofile.sh` (sourced directly) and `shell-aws-autoprofile.plugin.zsh` (the Oh My Zsh-loaded copy). Any change to one must be applied to the other in the same PR; byte-identity is enforced by `tests/run.sh` and the CI `cmp` gate. There is no build step and no dependency install.

Constraints for automated work, in priority order: tests establish behavior, not implementation — `tests/run.sh` runs the fixture suite under both bash and zsh, and `shellcheck -s bash` must stay clean (shellcheck has no zsh dialect; the plugin copy is covered by byte-identity). Proof runs on a Linux sandbox only: macOS shells, real Oh My Zsh installs, and hardware behavior are outside fixture reach and are recorded as unverified in `.obvious/QA.md`, never claimed as runtime-verified. No AWS credentials and no network calls in any workflow or test — fixtures are synthetic and disposable. PRs target `master` with squash merges; `AGENTS.md` and `.obvious/orientation.md` carry the deeper codebase map and line references.
